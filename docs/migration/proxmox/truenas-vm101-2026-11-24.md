# NAS TrueNAS sobre Proxmox

**24 de noviembre de 2026.** TrueNAS Community Edition 25.10.8 (Goldeye) quedó instalado en la VM 101. Se verificó el acceso al panel. El pool de datos queda pendiente de la incorporación del primer HDD de 8 TB.

## Decisiones de arquitectura

- Proxmox aloja dos VMs en el mismo puente LAN. Jarvis (VM 100) presta servicios de aplicaciones, DNS y HTTPS. TrueNAS (VM 101) administra el NAS.
- TrueNAS empleará ZFS desde el primer disco. La primera etapa incluye SMB autenticado, datasets separados, snapshots y monitoreo de disco según lo permita la conexión. El segundo HDD de 8 TB y la ampliación de RAM se prevén para abril o mayo de 2027.
- Immich queda previsto para la ampliación del host a 32 GiB. NFS se evaluará cuando exista un consumidor Linux. El respaldo de aplicaciones de Jarvis continúa en Restic en Windows.

## Instalación y verificaciones

1. Con Jarvis en marcha, Debian usaba 1,7 GiB y la swap estaba en cero. Se apagó la VM ordenadamente, se redujo la asignación fija de 6 a 4 GiB y se validó el arranque. Con siete contenedores activos, Debian reportó 2,1 GiB disponibles, swap en cero y presión de memoria nula durante la muestra.
2. AdGuard Home y Nginx Proxy Manager fallaron al publicar sus puertos antes de que DHCP entregara la dirección LAN. Se recuperaron manualmente y se verificaron DNS y los seis endpoints HTTPS. Se habilitó una unidad systemd que espera la IP y arranca ambos contenedores. La unidad terminó con código 0 con la red activa. Queda pendiente probarla en un reinicio planificado.
3. Se descargó TrueNAS 25.10.8 y se verificó el SHA-256 oficial. Se creó la VM 101 con 2 vCPU, 8 GiB fijos, q35, UEFI sin Secure Boot, VirtIO en `vmbr0` y un disco de arranque de 32 GiB en `local-lvm`. El arranque automático quedó deshabilitado.
4. Se recuperó la visualización de la consola antes de seleccionar el disco virtual de 32 GiB. Se eligió el administrador propio de TrueNAS. Se retiró la ISO, se arrancó desde el disco virtual y se verificaron el acceso web y la versión instalada.
5. Con ambas VMs en marcha, Proxmox reportó 4,8 GiB disponibles, 12 KiB de swap usada sin tráfico de swap, 99 % de CPU inactiva y sin espera de disco durante la muestra. El disco virtual de TrueNAS registró cero operaciones de E/S fallidas. Falta medir el host con el pool y tráfico SMB reales.

## Continuación

1. Reservar la IP de la VM 101 en DHCP e integrar DNS y monitoreo de Jarvis. El panel inicial responde por HTTPS con un certificado aún no confiable en Windows.
2. Conectar el HDD de 8 TB. El último inventario de Proxmox solo mostró el NVMe. Identificar capacidad, modelo y serie, revisar SMART y definir cómo presentar el disco físico a TrueNAS.
3. Crear el pool ZFS, los datasets y un recurso SMB autenticado. Probar lectura, escritura, permisos y recuperación de una versión. Definir una copia independiente para los archivos del NAS.
4. Reevaluar memoria y disco bajo carga. Preparar el espejo cuando llegue el segundo HDD y habilitar Immich después de ampliar la RAM.
