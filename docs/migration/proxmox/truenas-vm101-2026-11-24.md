# NAS TrueNAS sobre Proxmox

**24 de noviembre de 2026.** TrueNAS Community Edition 25.10.8 (Goldeye) quedó instalado en la VM 101. Se verificó el acceso al panel. Proxmox detecta el primer HDD de 8 TB. La autoprueba extendida terminó sin errores el 25 de noviembre. Quedan pendientes la asignación del HDD y la creación del pool ZFS.

## Decisiones de arquitectura

- Proxmox aloja dos VMs en el mismo puente LAN. Jarvis (VM 100) presta servicios de aplicaciones, DNS y HTTPS. TrueNAS (VM 101) administra el NAS.
- TrueNAS empleará ZFS desde el primer disco. La primera etapa incluye SMB autenticado, datasets separados, snapshots y monitoreo de disco según lo permita la conexión. El segundo HDD de 8 TB y la ampliación de RAM se prevén para abril o mayo de 2027.
- Immich queda previsto para la ampliación del host a 32 GiB. NFS se evaluará cuando exista un consumidor Linux. El respaldo de aplicaciones de Jarvis continúa en Restic en Windows.

## Instalación y verificaciones

1. Con Jarvis en marcha, Debian usaba 1,7 GiB y la swap estaba en cero. Se apagó la VM ordenadamente, se redujo la asignación fija de 6 a 4 GiB y se validó el arranque. Con siete contenedores activos, Debian reportó 2,1 GiB disponibles, swap en cero y presión de memoria nula durante la muestra.
2. AdGuard Home y Nginx Proxy Manager fallaron al publicar sus puertos antes de que DHCP entregara la dirección LAN. Se recuperaron manualmente y se verificaron DNS y los seis endpoints HTTPS. Se habilitó una unidad systemd que espera la IP y arranca ambos contenedores. La unidad terminó con código 0 con la red activa. Tras el apagado del host para instalar el HDD y el arranque manual de Jarvis, la unidad terminó con código 0. Desde Windows se verificaron la resolución DNS y la salud HTTPS de Vaultwarden.
3. Se descargó TrueNAS 25.10.8 y se verificó el SHA-256 oficial. Se creó la VM 101 con 2 vCPU, 8 GiB fijos, q35, UEFI sin Secure Boot, VirtIO en `vmbr0` y un disco de arranque de 32 GiB en `local-lvm`. El arranque automático quedó deshabilitado.
4. Se recuperó la visualización de la consola antes de seleccionar el disco virtual de 32 GiB. Se eligió el administrador propio de TrueNAS. Se retiró la ISO, se arrancó desde el disco virtual y se verificaron el acceso web y la versión instalada.
5. Con ambas VMs en marcha, Proxmox reportó 4,8 GiB disponibles, 12 KiB de swap usada sin tráfico de swap, 99 % de CPU inactiva y sin espera de disco durante la muestra. El disco virtual de TrueNAS registró cero operaciones de E/S fallidas. Falta medir el host con el pool y tráfico SMB reales.

## Primer HDD y diagnóstico

- Se apagaron ordenadamente ambas VMs y el host para instalar un WD Red Plus de 8 TB por SATA. El primer arranque mostró los seis enlaces AHCI caídos. En el segundo arranque se detectó el HDD en un enlace SATA de 6,0 Gb/s. Modelo WD80EFPX-68C4ZN0, capacidad de 8,00 TB nominales (7,3 TiB) y sectores de 512 bytes lógicos y 4096 físicos. La serie coincidió con la etiqueta y se verificó la ruta persistente por ID.
- La inspección inicial reportó SMART `PASSED`, 29 °C, cero sectores reasignados, pendientes o incorregibles, cero errores CRC y ningún error en el registro. `wipefs --no-act` no mostró firmas. Se registró un aviso de checksum inválido en la tabla de umbrales SMART.
- La autoprueba corta terminó sin errores. La extendida se inició con una estimación de 784 minutos. El 25/11 se verificó que la prueba extendida terminó sin errores, sin LBA fallido registrado. El HDD aún no fue asignado a TrueNAS.

## Organización del almacenamiento

| Carga | Ubicación acordada |
| --- | --- |
| Arranque y discos activos de VMs, Docker y configuración de servicios | NVMe del host, con discos locales de las VMs |
| Bases de datos activas (PostgreSQL, MariaDB y SQLite) | NVMe local a la VM. Exportaciones y copias consistentes en un dataset del NAS cuando corresponda |
| Fotos, videos, documentos y archivos de aplicaciones | HDD de 8 TB gestionado exclusivamente por TrueNAS con ZFS. Acceso SMB para Windows y NFS para consumidores Linux cuando se habilite |
| Copias secundarias de VMs, ISOs y archivos de laboratorio | Dataset del NAS. Las copias críticas deben quedar además fuera del host físico |
| Immich, previsto tras ampliar a 32 GiB | Aplicación y PostgreSQL en NVMe. Originales de fotos y videos en el NAS |

Los discos de arranque y las bases activas deben seguir disponibles aunque la VM 101 esté apagada. El NAS de un solo HDD podrá servir archivos a otros invitados. Los discos de VMs sobre NFS se reservan para pruebas. El respaldo de aplicaciones de Jarvis sigue en Restic fuera del host Proxmox.

## Continuación

1. Reservar la IP de la VM 101 en DHCP e integrar DNS y monitoreo de Jarvis. El panel inicial responde por HTTPS con un certificado aún no confiable en Windows.
2. Presentar el HDD a TrueNAS mediante la ruta estable por ID, en un slot distinto del disco de arranque y excluido del respaldo de la VM. Comprobar la identidad y capacidad desde el invitado antes de crear el pool.
3. Crear un solo pool ZFS con los datasets `Personal`, `Compartido` y `Fotos`, y habilitar SMB autenticado. Agregar `Backups-PC` con cuota una vez definido el alcance. Probar lectura, escritura, permisos y recuperación de una versión. Definir una copia independiente para los archivos del NAS.
4. Reevaluar memoria y disco bajo carga. Preparar el espejo cuando llegue el segundo HDD y habilitar Immich después de ampliar la RAM.

Los detalles de red e identificación del equipo se guardan en el registro operativo de Google Drive.
